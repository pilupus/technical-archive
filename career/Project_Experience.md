# Project Experience

## 신한라이프: 영업지원시스템 성능개선 프로젝트

* **기간**: 2025.11 ~ 2026.01
* **기술 스택**: Java, jQuery, WhaTap, Chrome DevTools
* **주요 내용**: 가입설계 **특약담보 전체선택 이벤트** 발생 시 발생하는 런타임 성능 병목 해결 및 브라우저 렌더링 최적화.
* **핵심 지표**: 스크립트 실행 시간 15s → 2s (약 86% 개선).
* **상세 업무 및 성과**:
  * **Algorithm**: 중복 루프로 구성되어 있던 기존 $O(n^2)$ 특약 연산 로직을 분석, 인메모리 해시 맵(Hash Map) 인덱싱 전략을 적용하여 $O(n)$으로 복잡도를 개선.
  * **Rendering Optimization**:
    * 기존의 무분별한 DOM 직접 조작으로 인한 렌더링 병목 현상을 식별.
    * 성능 극대화를 위해 `detach/append` 방식을 검토했으나, 레거시 환경의 이벤트 바인딩 안정성 및 메모리 정합성 유지를 위해 `hide/show` 기반의 디스플레이 제어 전략으로 선회.
    * 요소를 렌더 트리에서 일시 제외하여 레이아웃 계산을 억제함으로써 브라우저 CRP(Critical Rendering Path) 부하를 최소화.
  * **Performance**: 스크립트 실행 시간을 15초에서 2초로 단축(86% 개선)하여 대량의 특약 선택 시 발생하는 화면 프리징 현상을 해결.
  * **Memory Management**: JavaScript의 V8 엔진 GC 부하를 줄이기 위해 루프 내 불필요한 객체 생성을 억제하고, 재사용 가능한 자료구조를 설계하여 런타임 메모리 풋프린트를 최적화.

## 삼성증권: H.net 웹 전환 개발 프로젝트

* **기간**: 2025.07 ~ 2025.10
* **기술 스택**: JavaScript (ES6+), VBScript (Legacy), Git
* **주요 내용**: 레거시 VB Script 기반 금융 비즈니스 로직의 웹 표준 마이그레이션 및 파일 다운로드 인터페이스 이슈 해결.
* **핵심 지표**: 파일 다운로드 특이 케이스(Binary 수신) 분석 및 해결을 통한 기능 정상화.
* **상세 업무 및 성과**:
  * **Edge Case Identification**: 마이그레이션 공통 가이드로 처리가 불가능한 **파일 다운로드 기능 내 바이너리 데이터 수신 인터페이스**를 담당 화면의 특이 케이스로 식별.
  * **Technical Analysis**: AS-IS(VBScript)의 Binary 스트림 처리 방식과 JavaScript 런타임의 제약을 분석하여, 공통 함수가 정상 작동하지 않는 근본 원인이 데이터 규격(Binary)에 있음을 확인.
  * **Architectural Proposal**: 브라우저 환경에서 공통 기능을 안정적으로 활용하기 위해, Proxy 서버 계층에서 **Base64 인코딩**을 수행하도록 기술 요구사항을 정의하여 인터페이스 구조 개선 주도.
  * **Interface Mapping**: Proxy를 통해 표준화된 Base64 데이터를 JavaScript 공통 함수 인터페이스에 맞게 파싱 및 매핑하여, 담당 화면의 파일 다운로드 기능을 최종 완수.
  * **Migration Implementation**: 공통 전환 가이드에 따라 VBScript 비즈니스 로직을 JavaScript로 정밀하게 이식하고 데이터 정합성 검증 수행.

## 신한EZ손해보험: 영업시스템 고도화 프로젝트

* **기간**: 2025.04 ~ 2025.06
* **기술 스택**: Java, Spring, PostgreSQL, jQuery, Git
* **주요 내용**: 가입설계 프로세스 개편에 따른 데이터 세팅 로직 재설계 및 상태 보존 메커니즘 구현.
* **핵심 지표**: 단계 이동 시 데이터 유지율 100% 및 백엔드 의존성 제약 하의 프로세스 정상화.
* **상세 업무 및 성과**:
  * **Data Flow Redesign**: 기존 2단계(담보설계) 화면에 종속되어 있던 '고객필수정보' 세팅 로직을 1단계(계약사항)로 이전하여, 프로세스 초기 단계에서 필수 데이터가 선행 할당되도록 구조 개선.
  * **State Persistence Implementation**: 네비게이션 기능을 통한 비선형 단계 이동 시에도 1단계에서 세팅된 데이터가 휘발되지 않고 유지되도록 클라이언트 사이드 상태 관리 로직 구현.
  * **Zero-Backend Modification Strategy**: 백엔드 API 수정 없이 프론트엔드 레이어에서의 데이터 오케스트레이션(Orchestration)만으로 '계약사항 데이터 선행'이라는 서버 측 비즈니스 제약 조건 충족.
  * **Causality Control**: 1단계에서 전송된 데이터가 이후 모든 단계의 네비게이션 과정에서 정합성을 유지하도록 입력 시점과 API 호출 시점 간의 인과관계를 정밀하게 제어.
  * **Version Control**: Git을 활용한 형상 관리를 통해 대규모 로직 이전 및 네비게이션 신규 구현 과정에서의 소스 코드 정합성 확보.

## 한국사회보장정보원: 사회보장 통합플랫폼 유지관리 프로젝트

* **기간**: 2023.12 ~ 2025.03
* **기술 스택**: Java, Spring (eGov), Oracle, JavaScript
* **주요 내용**: 대규모 사회보장 전문 데이터 처리 아키텍처 개선 및 신청 체계 고도화.
* **핵심 지표**: 신청 구조 확장(1:1 → 1:N), 코드 표준 준수율 100%, 정책 대응 배포 공수 절감.
* **상세 업무 및 성과**:
  * **Data Mapping & Relationship Engineering**: 단일 신청ID당 1개 서비스만 매칭되던 기존 DB 구조의 한계를 극복하기 위해, 1개의 온라인 신청ID로 복수 서비스를 자동 분할 생성하는 로직 구현. 특히 **비사용 컬럼(Spare Columns)을 활용한 데이터 매핑 규칙 재정의**로 스키마 변경 없이 그룹 신청 기능을 성공적으로 도입.
  * **Service Module Normalization**: 서비스별로 파편화되어 있던 신청 정보 입력 모듈을 분석하여 **공통 신청 모듈** 체계로 통합 개발. 이를 통해 신규 서비스 추가 시 개발 공수를 단축하고 유지보수 일관성 확보.
  * **Policy-Driven Query & Validation**:
    * '해당 연도 수혜 횟수 제한' 지침 대응을 위한 대용량 이력 집계 쿼리 최적화 및 신규 개발.
    * 서비스 신청구분에 따른 '필수 구비서류' 자동 검증 로직을 구현하여 입력 단계에서 데이터 정합성 100% 확보.
  * **Static Analysis-Driven Refactoring**: 정적 분석 도구(AIQBot) 검출 결과를 바탕으로 표준 작명법을 위반하는 대규모 레거시 메소드를 전수 리팩토링하여 시스템 전체의 가독성 및 기술 부채 청산.
  * **Document Interface Development**: 바우처 신청서 및 사회서비스 이용권(신규/변경/중지) 통지서 등 신규 사업 지침에 따른 표준 서식 엔진 개발 및 데이터 바인딩 최적화.
